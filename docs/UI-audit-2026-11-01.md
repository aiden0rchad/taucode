# UI cohesion and resizing audit — 2026-11-01

Worktree: `taucode-m1w`, branch `m1-wiring`. Reference: Claude Desktop, inspected through Computer Use, including its session rail and browser splitter.

## Findings and changes

| Area | Finding | Change |
| --- | --- | --- |
| Sidebar dragging | Every pointer event saved localStorage and notified all React consumers. | Paint the latest position once per animation frame; save and notify on release, cancellation or focus loss. Keep the conversation width constraint. |
| Code dock dragging | Every movement rebuilt and saved the dock layout. Measurements also triggered renders for every pixel. | Update pane/divider geometry directly during drag, commit the split on release, render on compact-layout threshold crossings. Preserve mounted panes and drafts. |
| Shared shapes | Native rounded corners still ran SVG measurement work on resize. | Skip geometry work when CSS handles the shape. Keep the SVG fallback. |
| Window restoration | Repeated quit/relaunch checks showed the window shrinking. Geometry was sampled during final shutdown. | Capture the live window state at ExitRequested, then merge it after the window-state plugin writes at Exit. |
| Titlebar | At 90% UI scale, navigation overlapped macOS window buttons, which do not scale with the webview. | Scale-aware native-control inset and minimum titlebar height. |
| Session rail | Long empty sections and redundant environment text competed with useful information. | Compact environment controls, nested remote settings, quiet bordered sections, automatic empty-section collapse with explicit user choices retained. Errors remain visible. |
| Responsive rail | The session rail competed with chat as a dock pane, with redundant expand/close controls. | One list-style toolbar toggle; a 280px rail beside wide chats, a shared popover surface over chats below 840px of available width, and outside-click/Escape dismissal. The composer stays visible and drafts survive resizing. |
| Rail ordering | Header counts, a grip and an overflow menu crowded the disclosure chevron. | Title and chevron stay together; one subtle grip supports dragging and Up/Down keyboard reordering. Counts remain in accessible labels. |
| Rail material | The docked rail exposed the desktop directly while the conversation added a tint, creating a visible seam. | One theme-aware background spans the conversation and rail through the bottom of the window. Glass opacity is applied once; opaque themes share one gradient. |
| Code / Work sidebars | Projects need clear boundaries without excessive spacing. | Shared squircle project boxes, subtle borders, selected-project emphasis, 4px group gaps and tighter tree spacing; row heights remain unchanged. |
| Pane chrome | Dock headings were shorter than surrounding workspace controls. | Shared 40px heading height and consistent padding. |
| Settings navigation | Long section list required repeated scrolling. | Section/group-name filter, no forced navigation, clear-on-Escape and no-results state. |
| Project settings | Project names and paths were spread across a crowded row. | Name and truncated path on aligned separate lines. |
| Open in settings | Generic settings grid squeezed app fields into the right column. | Restore the wrapping row layout with sufficient selector specificity. |
| Feedback | A one-result command palette added a redundant step; empty search Enter still opened feedback, and the dialog had cramped fields and square corners. | Direct toolbar feedback action, full-width form fields, consistent shared dialog radius, Cancel before Save, and empty-note validation. |
| Update status | Installer instructions and buttons wrapped awkwardly inline. | Separate status, progress, action and error spacing. |
